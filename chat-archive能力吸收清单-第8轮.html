结论速览（推荐优先级）

一句话：第8轮核心 = 交互化 + 主动触达 + 分发工程，全部围绕让老板看得爽、被推送、用得上
P0-1 · report.html 交互化（零新依赖）
把 19 个模块数据内嵌为 JSON，加 vanilla JS 做筛选/Tab/搜索高亮（Observable/Evidence 静态编译范式 + Chatistics 正交筛选 flags）。当前 render_html.py 全文 0 行 JS。
来源：Observable Framework · Evidence · Chatistics｜成本 中｜商业化 高｜交互 ★★★★★
P0-2 · ECharts 图表三件套
内嵌 echarts.min.js（Apache-2.0，~1MB，构建时下载随包分发），新增日历热图（每日消息密度）+ 桑基图（发送者→分类→响应流向）+ 关系网络图（@提及/回复网络）。
来源：Apache ECharts · WhatsR 网络图｜成本 中｜商业化 高｜交互 ★★★★★
P0-3 · 消息时间线浏览 / 聊天回放
新增"像聊天记录一样翻回去看"的页面：按日分组吸顶、左侧成员侧栏过滤、搜索高亮、结论→原文跳转。审计/质检刚需。
来源：MemoTrace/WeChatMsg 查看器 · DiscordChatExporter｜成本 中｜商业化 高｜交互 ★★★★★
P0-4 · Webhook/邮件主动触达
未回复客户提问 + 商机/丢单信号实时推送（chatlog 三元组规则 talker+sender+keyword），对接钉钉/企业微信/n8n。把批处理报告升级为事件流——商业化价值最高。
来源：chatlog · 晓多丢单信号 · Throngwatch｜成本 中｜商业化 高｜交互 ★★★★
P0-5 · 多群汇总月报 + 员工排名导出
从"单次单群报告"升级为"跨群经营月报"，含员工考核排名，直接交付给老板看的成品（HTML，PDF 可后加）。
来源：网易七鱼数据大屏 · 微伴成员统计｜成本 中｜商业化 高｜交互 ★★★★
P0-6 · 合规 DISCLAIMER.md + 上游致谢
独立免责声明（"仅处理用户合法拥有的导出文件，不做内存取 key、不做数据库解密"）+ 上游工具来源致谢。PyWxDump 律师函事件后是生存底线，成本极低。
来源：chatlog · WechatBakTool｜成本 低｜商业化 高（保命）
P0-7(工程) · SQLite PRAGMA 加固
WAL+synchronous=NORMAL 之外补 busy_timeout=5000 + cache_size=-64000 + wal_autocheckpoint 调优（db.py 加 3 行），避免 Windows 下并发锁失败。
来源：SQLite 生产最佳实践｜成本 低｜收益 高
P0-8(工程) · PyInstaller 双平台分发
GitHub Actions matrix（windows-latest + macos-latest）出 onedir 包 + Release 自动发布。电商主管/运营不会 git clone + pip install——这是商业化分发门槛。
来源：PyInstaller · chatlog goreleaser｜成本 中｜商业化 极高
P0-9(工程) · CI 门禁 + 打包后 smoke test
pytest-cov 80% 门禁 + ruff + mypy + 打包后跑一次 chat-archive info 验证产物可执行。301 测试无门禁是当前最大工程风险。
来源：通用 CI 最佳实践｜成本 中｜收益 高

明确排除项（21 条，含原因）

#排除项来源原因
1内存取 key / 进程内存扫描 / 数据库解密PyWxDump · wechat-dump-rs · WechatBakTool合规红线：PyWxDump 已因律师函删库、腾讯公开点名；chat-archive 走"导入已导出明文"路线
2修改/删除微信消息、拦截朋友圈删除、防撤回 hookWeFlow写操作=入侵他人客户端，合规风险极高，电商归档场景无用
3实时自动回复/替人回消息句客宝秒回 · 晓多 · 美洽 bot实时写入=高封号风险；产品红线"只做读/分析，不做写/回复"
4企微官方会话存档接口对接微伴/尘锋/探马核心需企业认证+接口费+合规审批；做了反而和 SCRM 正面拼资源，破坏零门槛差异化
5GUI/Electron/Wails/WPF 桌面重写WeFlow · wechatDataBackup · WechatBakTool破坏纯标准库约束与 301 测试稳定性；report.html 已是可视化产物
6Streamlit / Dash / Gradio交互框架三件套依赖 ~300MB + 起常驻服务，与"替换 1 文件更新"的 CLI+Skill 形态冲突
7Metabase / Superset BIBI 平台JVM/Docker 运维成本对单机小团队不可接受；只借鉴"问题→下钻"模式
8FastGPT / Dify / RAGFlow 全栈部署RAG 平台Next.js+Mongo+PG Vector+Redis 运维过重；群聊级 RAG 需求远不需要完整平台
9在线 bot 常驻采集/IM 内发图telegram-analysis · telegram-stats-bot与离线归档、稳定第一、纯标准库约束冲突
10ChatLab 直接抄码ChatLabAGPL-3.0 网络传染性；只借鉴交互形态自行用 Python 重写
11iOS iTunes 备份解析路线WechatExporter场景不匹配（Windows PC 端微信群导出才是核心）；且 Android 群消息在 PC 微信才有完整副本
12呼叫中心/电话外呼七鱼 · 智齿 · 容联完全偏离群聊归档场景，硬件/资质重
13全渠道在线客服工作台七鱼 · 美洽 · Intercom替换客服系统的重 SaaS；chat-archive 是"赛后复盘"，正面做必败
14交易抽成模式快团团 · 群接龙不碰交易链路（规避合规）；差异化恰恰是不碰交易
15商城/卖课/知识店铺小鹅通 · 知识星球交易不做交付/交易载体，只做分析层
16通用 LLM agent 编排平台Dify/FastGPT 全量只做"群聊→结构化报告"垂直流水线，做通用平台是扬短避长
17按坐席人头收费的 SCRM 模式尘锋 1200 元/人/年按群/按产出物计费；按人头会把小群主挡在门外
18迁 CLI 到 Typer/ClickCLI 框架argparse 零依赖已够；在 ADR 固化决策防被"现代化"带偏
19Observable/Evidence/Quarto 作为构建工具静态报告框架Node 生态会把项目拖入双工具链；只借鉴"数据物化+浏览器端 reactive"范式
20Nuitka 默认打包 / Milvus·Qdrant·pgvector / LanceDB 主存储打包与向量生态Nuitka 构建慢需 C 编译器（仅杀软误报时备选）；独立向量服务是过度工程；LanceDB 引入 Rust 扩展打包复杂

结论与下一步

一句话结论：第 8 轮建议的核心是 "交互化 + 主动触达 + 分发工程"——交互化让老板看得爽（P0-1/2/3），主动触达让老板被推送（P0-4），分发工程让不会 Python 的电商运营用得上（P0-8）。三者全部落在零企微接口、纯本地、数据不出本机的差异化上，与 SCRM/客服 SaaS 正面错位。
节奏动作预期收益
第一个迭代（零新依赖）render_html.py 交互化（内嵌 JSON + vanilla JS 筛选/搜索/Tab）→ ECharts 三件套 → 消息时间线浏览report.html 从静态报表变交互看板，可演示给老板/客户
商业化第一步未回复客户提问 Webhook 推送 + 多群汇总月报（对接方向 1/3 的付费锚点）两条最直接的收费线：按信号命中数 + 按群月订阅
