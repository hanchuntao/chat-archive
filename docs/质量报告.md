## 2. 架构合理性评价

### 2.1 分层与职责（审计确认）

```
config.json（默认值/规则/阈值，行业词可换）
   │
   ├── 数据层 chat_archive/  （包，14 模块）
   │     db / search / stats / report / llm / vector / cli
   │     pipeline/{ingest, clean, desensitize}   ← 导入→清洗→脱敏 三段式
   │     importers/{wechat_json, plain}          ← 微信/QQ/企微/CSV 多格式识别
   │
   ├── 业务层 skill/scripts/chat_archive.py（单文件 CLI）
   │     all / stats / daily / summary / kb / assess / convert / kb-sync / kb-draft / verify
   │     每步 try/except 收 errors，尾部统一 exit 1 —— 无静默吞错
   │
   └── 辅助脚本 skill/scripts/{render_html, sync_kb, convert_wx}.py
```

- **数据层负责"确定性事实"**（入库/检索/统计/脱敏），**业务层负责"业务语义"**（员工识别/日报/考核/知识库/跟进）——职责不重叠，测试可分层打击。
- **skill/ 即交付物**：符号链接挂载到豆包/Claude/Codex/WorkBuddy/DeepSeek 的 `.user_skills/chat-archive`（已验证 `lrwxr-xr-x`），改 `skill/` 即全生效，无需部署、无需安装依赖。
- **SQLite 决策**（用户拍板）：单文件、零服务、WAL + synchronous=NORMAL + FTS5 全文检索，对 10 人电商群的统计/过滤/知识沉淀量级完全够用；不做 PostgreSQL（用户明确拒绝）。

## 5. 三重路径交叉验证（实测结果）

对同一输入 `sample_data/ecom_chat.txt` 跑三条独立路径：

| 路径 | 命令 | 实测结果 |
|---|---|---|
| A. 数据层 CLI | `chat-archive.py --db /tmp/tri_a.db init → import → search "发货" → stats --group sender → info → backup` | ✅ init 建库；import 49 条（脱敏审计 138****5678）；search 5 条命中；stats 按 sender 计数对齐（张三 12/李四 6/王五 6/赵六 6）；info 49 条 + 时间范围正确；backup 可读 49 条 |
| B. 业务层全流程 | `skill/scripts/chat_archive.py all --input sample_data/ecom_chat.txt --staff all --out /tmp/tri_b` | ✅ [28/28] 全部完成；快照 63 个产物；`verify --input <快照>` → `ok: true`（63 checked，无缺失/多余/篡改）；篡改 report.html 后重验 → `tampered: [report.html]` + exit 1 |
| C. 单元直调 | `pytest tests/` | ✅ 296 passed（与 A/B 同一输入同一断言，内存态与文件态一致） |

**一致性结论**：A/B/C 三路在员工消息数、检索命中数、产物清单三个断点上完全一致。`--mask-all` 全链路无明文 PII 已验证（员工 490/534/791 匿名化、考核逻辑仍正确）。

## 7. 残留风险与后续建议（可选增强，非阻塞）

1. **LLM 提炼为可选**：config 未配 API Key 时规则模式兜底，实测全链路可用；配 Key 后 `report`/`summary`/`assessment_notes` 走 AI 提炼。建议商业部署时接入企业 LLM 网关。
2. **向量语义检索为可选**：chromadb 非默认依赖，测试 mock 覆盖；10 人群量级下 FTS5 关键词检索已够用。
3. **定时自动运行**：`all` 全流程本身是纯 CLI，可与 cron/定时任务技能配合每日自动跑；当前 Skill 形态为"用户提供文件→一键整理"，未内置调度（符合用户拍板的形态）。
